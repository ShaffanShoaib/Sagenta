# ADR-001: Authentication Flow and JWT Strategy

Status: accepted

## Context
The project requires a robust and secure user authentication system. Given the stateless nature of web APIs and the need for efficient authorization, a token-based approach is preferred. Existing architectural decisions and tickets point towards using JSON Web Tokens (JWTs).

## Decision
Implement a JWT-based authentication system. Access tokens will be short-lived (e.g., 15 minutes) and stored in client-side memory (e.g., global state). Refresh tokens will be long-lived (e.g., 7 days), stored in secure, http-only cookies, and used to obtain new access tokens without requiring re-authentication. This strategy balances security (short-lived access tokens, http-only refresh tokens) with user experience (seamless token refresh).

## Consequences
- Requires secure handling of refresh tokens on the backend (http-only cookies, potential database storage for revocation).
- Backend must provide endpoints for token generation, verification, and refresh.
- Frontend must implement mechanisms to store/retrieve access tokens, attach them to requests, and handle token expiration/refresh gracefully.
- Stateless access tokens simplify scaling but necessitate a mechanism for immediate token revocation if required (e.g., a blacklist or short expiration with frequent refresh).
